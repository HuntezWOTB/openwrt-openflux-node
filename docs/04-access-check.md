# 04. Если документ запросил проверку: куки через панель

Иногда облако просит подтвердить доступ (подозрительный адрес, новый вход).
Нода сама проходит простые автоматические проверки, а интерактивную покажет
в журнале строкой про необходимость внешней помощи. Тогда помогаем руками —
строго из домашней сети, чтобы внешний адрес браузера совпал с адресом роутера.

## Порядок

1. Откройте тот же URL документа в браузере из домашней сети.
2. Пройдите проверку, убедитесь что документ открывается.
3. `F12 -> Application -> Cookies -> <домен документа>` — скопируйте значения.
   Быстрый способ: вкладка `Console`, команда `document.cookie` — даст строку
   `a=b; c=d; ...`. Служебные `HttpOnly`-куки туда не попадают, допишите их
   вручную из таблицы (`i`, `sessar`, `skid` и подобные).
4. В `Службы -> OpenFlux`, блок проверки доступа, вставьте итог в поле
   `Куки для документа`. Форматы на выбор:
   - `a=b; c=d` (из `document.cookie`),
   - построчно `a=b`,
   - Netscape `cookies.txt` целиком,
   - JSON `{"a":"b"}`.
5. `Сохранить + Применить`. Сервис при старте перепакует вставку в файл
   из поля `Файл кук` в формате `{"<URL>": {имя: значение}}` и перезапустится.

## Проверка

```sh
ls -l /tmp/cookies-*.json
/etc/init.d/openflux stop; sleep 2; /etc/init.d/openflux start
sleep 15
logread -e openflux | grep -E "DOCS|CAPTCHA|Smart|SESSION|Running" | tail -20
```

Если проверка ушла — в логе подключение к документу и `waiting for a client`.
Если осталась — допишите недостающие куки из таблицы браузера.

Замечание: куки живут ограниченно, проверку придется повторять. Если проверки
частые — заведите второй документ у другого облачного провайдера и держите
два транспорта (см. README про мультитранспорт в upstream).
